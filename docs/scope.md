# Project Scope Statement

**Project Name:** SPD-to-OR

## Project Purpose
**Why are we doing this project?**

The purpose of this project is to create a simple two-page website that explains how Sterile Processing supports the operating room and patient care. I chose this topic because I have worked as both a surgical technologist and in Sterile Processing, so it is something I already have experience with. The project also gives me a chance to use the HTML, CSS, GitHub, and project management skills I learned in this course in one final project.

## Feedback Loops
**Who needs to provide feedback? When and how?**

The main feedback will come from the course instructor through the project directions, rubric, and final evaluation. I will also review the website myself as I work instead of waiting until the end. Before submitting, I will test both pages, check the navigation and live website, review the repository structure, and compare the finished project to the final rubric.

## Description
**How would you describe this project?**

I will create a two-page informational website about the connection between Sterile Processing and the operating room. The homepage, `index.html`, will explain what Sterile Processing does and why its relationship with the OR matters. The second page, `about.html`, will explain the basic journey of surgical instruments from the OR, through Sterile Processing, and back to the OR.

Both pages will use one external stylesheet, `style.css`, so the design stays consistent. The project will be stored in a public GitHub repository and published through GitHub Pages. The repository will also include a README and a `docs/` folder containing the project scope, plan, and retrospective.

## People Resources
**Who are the key team members?**

- Patrick Casey - project manager, developer, and content creator
- Course instructor - stakeholder and final evaluator

This is an individual project, so I am responsible for planning, building, testing, documenting, and submitting the project.

## Desired Results
**What specific outcomes must we achieve to be successful?**

- Create a working `index.html` homepage.
- Create a working `about.html` second page.
- Use one external `style.css` file for both pages.
- Clearly explain the basic relationship between Sterile Processing and the operating room.
- Explain the basic instrument workflow without using patient information or employer-specific information.
- Include working navigation between both webpages.
- Publish the website through GitHub Pages with a working public link.
- Keep all project files in one organized public GitHub repository.
- Include a `docs/` folder with `scope.md`, `plan.md`, and `retrospective.md`.
- Include a `README.md` that explains the project and links to the live site and documentation.
- Test the pages, navigation, and links before final submission.

## Budget
**What is the budget?**

## Exclusions
**What is out of the project's scope and should NOT be included?**

The website will not include patient information, confidential workplace policies, internal documents, or anything specific to my current employer. It will not provide medical advice, give step-by-step instructions for performing a surgical procedure, or replace device instructions for use.

The project will not include JavaScript, databases, user accounts, forms, advanced animations, extra webpages, or other features outside the required two-page HTML and CSS prototype.
